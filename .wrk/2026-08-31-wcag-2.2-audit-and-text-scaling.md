# WCAG 2.2 audit and persistent text scaling

Date: 2026-08-31 (Asia/Bangkok)

## Delivered scope

- Product website: a subtle header accessibility control opens a localized dialog with `A-`, `A+`, `Reset` and a 100-200% range in 10% increments. The value is stored only in the visitor's browser and is applied before first paint.
- Eduvixo administration: identical text scaling is integrated into the existing Interface settings panel. No additional top-level icon or competing settings panel was added.
- School frontend: both the official Eduvixo Theme and the separate production Shoudu Theme contain localized accessibility controls, skip links, visible focus, persistent scaling and reduced-motion handling.
- Dialog behavior: focus is moved into newly opened accessibility and announcement dialogs, Tab/Shift+Tab remain inside modal content, Escape closes where appropriate and focus returns to the initiating control.
- Contrast and accessible-name corrections cover the Marketplace result count, Demo login submit button, Shoudu popup eyebrow, values/motion copy, admissions CTA and film control.
- The remaining em dash characters in the covered administration and Shoudu sources were replaced with normal hyphens as required by the project style rule.

## Languages

The public product website accessibility copy is complete in `de`, `en`, `lo`, `pl`, `th`, `vi` and `zh`. The Shoudu school theme uses its supported `en`, `km` and `zh` locales. Every control has a localized accessible name, visible label or both.

All 592 public translation keys match across the seven product languages. The audit found no missing/extra keys, empty values, invalid spacing, hidden control characters, Unicode replacement characters, em dashes or placeholder mismatches.

## Deployment findings and permanent corrections

The first core attempt stopped before file/database mutation because a multi-installation deployment process passed inherited `CMS_*` variables from Shoudu into the Demo updater. The bootstrap now clears inherited `CMS_*` values before loading the target installation. This fixes the root cause without bypassing license validation.

The first Shoudu theme validation installed the signed package successfully but checked the hard-coded `themes/eduvixo/theme.json` path. The theme bootstrap now accepts and validates an explicit expected slug and reads the corresponding manifest. The final state was re-audited after both corrections.
