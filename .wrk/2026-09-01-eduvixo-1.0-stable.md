# Eduvixo 1.0 Stable - production release

Date: 2026-09-01

## Scope and identity

- Licensed product generation: Eduvixo 1.0.
- Production build: 1.0.9.
- Release channel: Stable.
- Runtime: PHP 8.2+, MySQL 8.0.29+ or MariaDB 10.5+.
- Targets: `www.eduvixo.com`, `demo.eduvixo.com`, and `shoudu.lrn.asia`.

The product generation remains `1.0`; the independently incremented build number is `1.0.9`. Optional provider integrations and the portable Windows preview retain their own lifecycle and are not represented as Stable core capabilities.

## Implementation

- Bound the signed core manifest and update verification to the declared release engine and channel.
- Added an immutable clean-installer builder that excludes secrets, runtime data, symbolic links, development directories, and the Shoudu theme.
- Added an end-to-end release verifier for signed core contents, clean installer boundaries, Marketplace artifacts, language parity, and UI regressions.
- Corrected fresh-install theme seeding to use the bundled Eduvixo theme manifest version.
- Recorded build and release channel in new installation metadata while preserving the licensed `1.0` product boundary.
- Added repeatable migration coverage for system notifications and Web Push.
- Fixed the backend text-scale selector: the `100%` output now targets only `output[data-text-scale]` and can no longer replace the document root.
- Updated all seven public languages with the Stable release date, summary, and six release highlights.

## Backup and recovery

Pre-deployment backup:

`/root/eduvixo-backups/eduvixo-1.0-stable-pre-20260901-063827`

It contains transactional SQL dumps and complete filesystem archives for both CMS installations plus the public website archive. Files are mode `0600` and were size/checksum validated before deployment.

Updater recovery points:

- demo: `recovery-44068f121f78f7ab1f117184`
- shoudu: `recovery-fef5fc739a7f2ce9d8c047c4`

Rollback order:

1. Put only the affected installation into maintenance mode.
2. Prefer its updater recovery point to restore the previous files and database atomically.
3. If updater recovery is unavailable, restore the matching filesystem archive and SQL dump from the pre-deployment backup.
4. Restore the website archive only when the public catalog or website is affected.
5. Reapply the recorded owner/group, clear maintenance mode, then rerun the production, security, and update audits.

Do not restore one installation's database or filesystem into the other installation.
